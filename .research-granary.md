## 1. Which model/step restores punctuation and capitalization?

**Qwen2.5-7B-Instruct, run with vLLM, as the last text step of the ASR pipeline.**

Paper, §3.1.5 "LLM-Powered P&C Restoration"
(https://ar5iv.labs.arxiv.org/html/2505.13404):

> "The Granary corpus relies on pseudo-labeled data from Whisper, necessitating steps to
> enhance quality and reduce dependence on Whisper's performance. To address this, we
> applied punctuation and capitalization restoration using the large language model
> Qwen 2.5-7B-Instruct."

> "We crafted a language-specific prompt directing the model to assess and correct
> punctuation and capitalization, supplemented by multiple correction examples. To
> maintain output quality, we implemented character set filtering and Qwen hallucination
> filtering. A heuristic was used: if Qwen's output deviated from Whisper's transcriptions
> by more than a 5% character error rate, the original pseudo-labels were retained."

HF dataset card (https://huggingface.co/datasets/nvidia/Granary/raw/main/README.md):

> "4. **P&C Restoration**: Qwen-2.5-7B for punctuation/capitalization normalization"

SDP README (https://github.com/NVIDIA/NeMo-speech-data-processor/blob/main/dataset_configs/multilingual/granary/README.md):

> "**PnC restoration** (21–23) – `Qwen-2.5-7B` restores punctuation & capitalisation; optional regex clean-up."

`config.yaml` uses `model: "Qwen/Qwen2.5-7B-Instruct-1M"`, `temperature: 0.7`, `top_p: 0.8`,
prompt file `partials/pr_recovery_prompts/${params.source_lang}.yaml`.

### The exact German prompt (this IS the German style spec)

`partials/pr_recovery_prompts/de.yaml`
(https://raw.githubusercontent.com/NVIDIA/NeMo-speech-data-processor/main/dataset_configs/multilingual/granary/partials/pr_recovery_prompts/de.yaml):

> "Regeln:
>   - Ändern, hinzufügen oder entfernen Sie keine Wörter im Text. Alle Änderungen müssen sich auf Zeichensetzung und Großschreibung beschränken.
>   - Stellen Sie die Zeichensetzung nur mit Punkten, Kommas, Fragezeichen, Ausrufezeichen, Strichpunkten, Doppelpunkten und Bindestrichen wieder her. Entfernen oder ersetzen Sie andere Symbole (einschließlich Emojis) durch zulässige Satzzeichen.
>   - Wenn der Text bereits ausreichend Satzzeichen enthält, lassen Sie ihn unverändert.
>   - Korrigieren Sie unvollständige oder fehlerhafte Zeichensetzung.
>   - Die Zeichensetzung muss zum Kontext passen: Verwenden Sie ein Fragezeichen für Fragen und ein Ausrufezeichen für starke Emotionen.
>   - Schreiben Sie den ersten Buchstaben jedes Satzes groß.
>   - Schreiben Sie Eigennamen und Abkürzungen groß.
>   - Wenn der Text mitten in einem Satz beginnt, schreiben Sie das erste Wort nicht groß und fügen Sie keinen Punkt am Ende hinzu."

Key consequences for yappr:
- **No word may be added, changed or removed.** So the LLM step is not a rewriter; it
  cannot delete fillers or reformat numbers.
- Allowed punctuation set is small: `. , ? ! ; : -`. Quotation marks are NOT in the set.
- **Explicit rule: a segment that starts mid-sentence keeps a lowercase first word and gets
  NO final period.** This is why parakeet-v3 output often has no terminal punctuation and
  no leading capital — the training targets are like that by design.

One of the German few-shot examples in the same file shows digits being kept verbatim:

> - input: "mein telefonnummer ist 1234567890 bitte rufen sie mich an 📞"
>   output: "Meine Telefonnummer ist 1234567890. Bitte rufen Sie mich an."

### Post-LLM guard (`CleanQwenGeneration`)

https://raw.githubusercontent.com/NVIDIA/NeMo-speech-data-processor/main/sdp/processors/inference/llm/utils/qwen_cleaning.py

> "A processor that filters and post-processes model generations, replacing them with
> reference text if they are considered low quality based on character error rate (CER)
> and uppercase letter proportion."

Defaults in code: `cer_threshold=10`, `upper_case_threshold=0.6` (the paper says 5%; the
config does not override the default, so the shipped pipeline uses 10). When the guard
fires, the **raw Whisper text is kept**, i.e. some released segments are plain Whisper
output, and some are effectively unpunctuated lowercase (see §6 measurements).

## 2. Is inverse text normalization (ITN) applied? Digits or words?

**There is no ITN step and no verbatim/spoken-form normalization step.** The pipeline
never converts numbers. The text keeps whatever written form Whisper-large-v3 emitted,
which for Whisper is digits. The pipeline then *labels* that text as ITN-style.

`config.yaml`, processor 44 (`AddConstantFields`)
(https://raw.githubusercontent.com/NVIDIA/NeMo-speech-data-processor/main/dataset_configs/multilingual/granary/config.yaml):

```yaml
  - _target_: sdp.processors.AddConstantFields
    output_manifest_file: ${output_dir}/${params.source_lang}/manifest_44.json
    fields:
      decodercontext: ""
      "emotion": "<|emo:undefined|>"
      "pnc": "pnc"
      "itn": "itn"
      "timestamp": "notimestamp"
      "diarize": "nodiarize"
```

SDP README:

> "**Constant flags (44)** – add decoder directives (``<|emo:undefined|>``, *itn*, *pnc*, etc.)."

So every Granary sample is tagged `itn` + `pnc`: the target text is treated as
**written form with punctuation and capitalization**. This is a label, not a conversion —
no NeMo ITN/`nemo_text_processing` processor appears anywhere in the config.

The only text-shaping step is a regex substitution list (`SubRegex`, processor 23), driven
by `params.use_regex` (default `common`).

`partials/subregex_params/common.yaml` keeps digits and `:`/`/` in its allow-list:

> `- {"pattern": "[^ !$%',-.0123456789;?ABCDEFGHIJKLMNOPQRS...€₴₽/:]", "repl": " "}`

and normalizes typography:

> ```
> - {"pattern": "’", "repl": "'"}
> - {"pattern": "—", "repl": "-"}
> - {"pattern": "–", "repl": "-"}
> - {"pattern": ";", "repl": ","}
> - {"pattern": '\[[^\]]*\]', "repl": ""} # delete content inside []
> - {"pattern": ' ?\([^\)]+\)', "repl": ""} # delete content inside ()
> - {"pattern": ' ?{[^}]+}', "repl": ""} # delete content inside {}
> ```

Note: there is also a German-specific preset `partials/subregex_params/de.yaml` that would
map `ß -> ss` and delete `:` and `-`. **Measurement on the released German manifests shows
it was NOT used** — `ß` occurs frequently and `:` occurs — so German was processed with the
`common` preset.

**Empirical answer (measured on 11,834 released German ASR segments, yodas + ytc):**
- 8.8% of segments contain at least one digit; spelled-out number words
  (`zwanzig|dreißig|hundert|tausend|zwölf|siebzehn`) appear in only 15 segments (0.13%).
- Numbers appear as digits, German-style: decimal comma `10,86`, `96,1 %`, `1,85 %`;
  thousands dot `20.000`, `10.000 Euro`, `1.575`, `150.000`.
- Dates: `am 14. Januar`, `am 26. Januar`, `am 18. Mai`, `4. Juni` (digit + ordinal dot).
- Times: `um 9 Uhr`, `Montag, 20 Uhr`, `0 Uhr` — digits + `Uhr`. No `14:30`-style clock
  time was seen in the sample; `:` occurs only as a colon punctuation mark
  (`Jetzt zum Beispiel: Google hat auch sehr`).
- Percent as symbol: `70%`, `20% weniger`, `1 %`, `96,1 %` (spacing inconsistent).
- Character inventory of the whole German sample, excluding letters/digits/space:
  `! % & ' , - . : ? ¿ –` — i.e. **no quotation marks at all**, no semicolons,
  no €/$ in this sample, no brackets, no ellipsis.

## 3. Disfluencies, fillers, hesitations, false starts

**Not removed.** No processor removes filler words, and the P&C prompt forbids it
("Ändern, hinzufügen oder entfernen Sie keine Wörter im Text").

What the pipeline *does* remove are hallucinations, at whole-segment granularity:

Paper §3.1.4 "Robust Data Filtration":

> "First, we eliminate instances where any of the three hallucination flags are active,
> signaling the presence of *i)* repeated n-grams, *ii)* long words, or *iii)* frequently
> hallucinated phrases. The latter is particularly noteworthy; leveraging custom
> modifications to Whisper-large-V3 and V3-turbo, we compiled language-specific lists of
> commonly hallucinated phrases. These include both specific terms, such as
> ”Sous-titrage Société Radio-Canada” in French, and broadly used expressions like
> ”Thank you very much”."

> "Character rate filtering is another crucial step. Using language- and corpus-specific
> heuristics, we eliminate speech-transcription pairs with anomalously low or high
> character rates..."

Implementation (`whisper_hallucinations.py`): `hall_repeated_ngrams` (unique-word share
<= 0.4), `hall_long_word` (>= 25 chars), `hall_frequent_single_word` — the last matches
the **whole cleaned transcript** against the phrase list:

```python
def frequent_single_word(self, text):
    cleaned_text = text.strip().replace('.', '').replace('?', '').replace('!', '')
    return cleaned_text in self.common_hall_phrases
```

So it drops a segment whose entire text is e.g. "Ja" or "Vielen Dank"; it never edits
text inside a segment.

German hallucination phrase list (`partials/common_phrases/de.txt`), complete file:

```
Ja 734
Vielen Dank 518
Entschuldigung 174
Dank 150
Wer ist dafür 81
Enthaltungen 65
169 in Fiverr 58
Dagegen 57
```

**Measured:** 0.5% of the 11,834 German segments contain `äh|ähm|ehm|öhm|hm`, e.g.
`"Sie kreuzen doch nicht Marion, äh, Steffen hinterher."`, `"Ähm, ja."`,
`"Äh, gezählt, aber nicht markiert."`. So fillers survive, but they are rare — mostly
because the *teacher* (Whisper) tends not to transcribe them, not because of a filter.

## 4. German (de) data in Granary

- Sources for German: **YODAS (YouTube), YouTube-Commons (ytc), VoxPopuli** — the HF card
  lists `de/yodas`, `de/voxpopuli`, `de/ytc` (no LibriLight, that is English only).
- Hours: the Granary paper gives per-language hours only as a log-scale figure (Fig. 3).
  The Parakeet/Canary report Appendix A gives usable numbers
  (https://ar5iv.labs.arxiv.org/html/2509.14128):

  > "de  29279.61  2602.24  28974.96  2509.15  8781.31  20267.06"

  columns `Lang | ASR Granary | ASR NeMo | X→En Granary | X→En NeMo | En→X NeMo | Supplementary`,
  so **~29,280 h German ASR from Granary** plus ~2,602 h from NeMo ASR Set 3.0.
- German is one of the few languages where VoxPopuli does *not* dominate:

  > "Except for high-resource, well-represented languages such as German, Spanish, French,
  > Italian, Portuguese, and Russian, the Voxpopuli subset of the Granary corpus dominates,
  > comprising over 95% of the data for most languages. This dominance of Voxpopuli creates
  > two primary issues for these languages: (a) Voxpopuli recordings originate from EU
  > parliament sessions, where the language register differs significantly from everyday
  > conversational speech..."

  So German has a comparatively large share of YouTube (YODAS/YTC) conversational speech.
- Quality filtering for German is the generic pipeline: Whisper LID must equal `de` with
  `language_probability >= 0.7` (`min_audio_lid_probability`, and `< 0.8` samples excluded
  for VoxPopuli per paper §3.1.3), hallucination flags, character-rate and charset filters,
  0.1–40 s duration window.
- Casing: `ß` is preserved, umlauts preserved, no quotation marks. Nouns are capitalized
  normally by Qwen; **but ~12% of segments have no uppercase letter at all** (see §6).

## 5. Teacher model and its number/punctuation behaviour

Paper §3.1:

> "Building on prior research [6], we identified Whisper-large-v3 [11] as a strong
> candidate for pseudo-labeling due to its robust performance, multilingual capabilities,
> and open license."

> "...we initiated the Whisper-large-V3 pipeline using FasterWhisper [15] with a beam size
> of 5 and a chunk batch of 16. Following MOSEL's best practices [6], we performed two-pass
> inference: first for language ID prediction, then for transcription..."

`config.yaml` confirms `model_size_or_path: 'large-v3'` for all three inference passes
(LID pass, pass 1, pass 2). Parakeet used `parakeet-tdt_ctc-110m` timestamps only for
LibriLight segmentation, not for labels.

The paper also names Whisper's casing weakness as a motivation for the P&C step:

> "Additionally, language identification errors, fixed 30-second segment requirements, and
> lack of case control in output text further complicate its use."

Whisper-large-v3's known text style (this is the style Granary inherits):
- It was trained on web transcripts, so it emits **written/ITN form**: digits, currency
  symbols, `%`, abbreviations — not spoken form. Confirmed empirically on the released
  German manifests above.
- It emits punctuation and casing, but inconsistently, and it usually **omits
  disfluencies** rather than transcribing them.
- Whisper's own eval normalizer removes punctuation and casing and converts spelled-out
  numbers to digits, which is why the model cards report WER "after removing Punctuation
  and Capitalization". Parakeet report §6.1:

  > "We use the Hugging Face Open Automatic Speech Recognition Leaderboard normalizers ...
  > the English normalizer for English test sets, and the newly added multilingual
  > normalizer for non-English test sets. Both remove punctuation and lowercase the text."

  Meaning: **no published WER number measures Granary/parakeet punctuation or casing
  quality at all.**

Parakeet v3 model card (https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3/raw/main/README.md):

> "* Automatic **punctuation** and **capitalization**"
> "**Other Properties Related to Output:** Punctuations and Capitalizations included."
> "All transcriptions preserve punctuation and capitalization."

Neither the parakeet-v3 nor the canary-1b-v2 card mentions ITN or number formatting.

Non-speech robustness (relevant to short/empty dictations), Parakeet report §3.2:

> "To enhance model robustness against hallucinations, particularly those potentially
> inherited from Whisper-based pseudo-labeling, we incorporated 36,000 hours of non-speech
> audio into our training dataset. These samples ... are paired with empty string targets
> to teach the model when not to generate transcriptions."

## 6. Measurements on the released German ASR manifests

Method: HTTP range read of the first ~3 MB of
`de/yodas/de_asr.jsonl` and `de/ytc/de_asr.jsonl` from
`https://huggingface.co/datasets/nvidia/Granary/resolve/main/`, 11,834 segments total.

| property | share |
|---|---|
| starts with a lowercase letter | 20.7% |
| does not end in `.` `?` `!` | 28.1% |
| contains no `.` `,` `?` `!` at all | 11.8% |
| contains no uppercase letter at all | 12.4% |
| contains at least one digit | 8.8% |
| contains `äh`/`ähm`/`hm` | 0.5% |

Final-character distribution: `.` 7621, `,` 700, `?` 685, `!` 203, plus ~2,600 segments
ending in a bare letter.

Representative segments:

- `"Wer ist Artikel 231 Absatz 4 der Geschäftsordnung, gilt diese Berichtigung als angenommen. Wenn nicht binnen 24 Stunden von einer Fraktion oder mindestens 40 Mitgliedern beantragt wird, ..."`
- `"Die endgültige Verabschiedung ist am 26. Januar vorgesehen."`
- `"Ich finde die letzte Preiserhöhung mit 1,85 % bzw."`
- `"Tagesordnungspunkt 40, Drucksache 19-5745 zu Drucksache 19-5200."`
- `"kann ich Ihnen sagen."` (lowercase start, no terminal period — the mid-sentence rule)
- `"gut gut es stimmt ich kann ja jetzt jedes mal ein ding ist sie auf die drauf packen perfekt"`
  (a segment where the Qwen output was rejected, so raw lowercase Whisper text survived)

## 7. What this means for yappr

1. **Expect written-form numbers from parakeet-v3.** Digits, decimal comma, thousands dot,
   `%`, `19-5745`-style compounds, `9 Uhr`. Do not add an ITN step; do not expect the model
   to spell numbers out.
2. **Expect missing terminal punctuation and missing initial capital on roughly a fifth to a
   quarter of utterances.** This is trained-in behaviour from the Granary prompt rule about
   mid-sentence segments, not a bug. `finish::finish` (invariant 8) is therefore doing
   exactly the right job, and it is load-bearing for German dictation.
3. **Expect no quotation marks ever**, and a punctuation inventory limited to roughly
   `. , ? ! : -`. Semicolons were mapped to commas in training data.
4. **Expect fillers to be mostly absent but occasionally present** (`äh`, `ähm`). Nothing in
   the training data removes them systematically, so a normalizer that deletes them is a
   product decision, not a correction of the ASR.
5. **Expect ~12% "raw Whisper" style output patterns** (fully lowercase, unpunctuated) as a
   learned mode, most likely on fast, casual, YouTube-like speech — which is exactly what
   dictation sounds like. That is a further argument for a deterministic finishing step
   plus the S1-mini normalizer rather than trusting ASR casing.
6. `ß` and umlauts are safe: the German data used the `common` regex preset, not the
   `ß -> ss` German preset.
