## 1. Base model, architecture, tokenizer

Model card (https://huggingface.co/superwhisper/s1-mini/raw/main/README.md):

> | Type | Causal language model, fine-tuned for a single transformation task |
> | Base model | [Qwen/Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B) |
> | Parameters | 596M total (0.44B non-embedding), embeddings tied |
> | Layers | 28 |
> | Attention heads | 16 for Q, 8 for KV (GQA) |
> | Precision | BF16 |
> | Recommended input | Up to ~1,000 tokens; chunk longer transcripts |
> | Language | English |

`config.json` (https://huggingface.co/superwhisper/s1-mini/raw/main/config.json):

```json
{"architectures":["Qwen3ForCausalLM"],"model_type":"qwen3","hidden_size":1024,
 "intermediate_size":3072,"num_hidden_layers":28,"num_attention_heads":16,
 "num_key_value_heads":8,"head_dim":128,"max_position_embeddings":40960,
 "rope_theta":1000000,"tie_word_embeddings":true,"torch_dtype":"bfloat16",
 "vocab_size":151936,"transformers_version":"4.51.0"}
```

Tokenizer: unchanged Qwen3 tokenizer. `tokenizer_config.json` has
`"tokenizer_class": "Qwen2Tokenizer"` (byte-level BPE, `vocab.json` + `merges.txt`),
`vocab_size` 151936, `eos_token` `<|im_end|>` (151645), `pad_token` `<|endoftext|>`
(151643), `model_max_length` 131072. No new special tokens were added for the control
line — `[Styling: ...]` etc. are plain text.

**German relevance:** the tokenizer and the base model are already multilingual. The
Qwen3-0.6B card says: "**Support of 100+ languages and dialects** with strong
capabilities for **multilingual instruction following** and **translation**"
(https://huggingface.co/Qwen/Qwen3-0.6B/raw/main/README.md). German is well inside that
set, and umlauts/ß cost no extra vocabulary work. So a German finetune does not need a
tokenizer change or vocabulary extension.

Parameter-count gotcha, straight from the card:

> The Hub sidebar reports 0.8B parameters for this repo. `config.json` sets
> `tie_word_embeddings`, but `model.safetensors` still stores `lm_head.weight` as a
> materialized copy of the input embedding, so the 155.6M-parameter embedding is counted
> twice: 751.6M tensor elements against 596.0M unique parameters.

For training this matters only in one way: after finetuning, save with the same layout
(tied config + materialized `lm_head`) so the existing `convert_hf_to_gguf.py` path and
llama.cpp keep working.

## 2. Are unquantized weights published? — YES

`https://huggingface.co/api/models/superwhisper/s1-mini/tree/main` lists:

```
LICENSE 12033, NOTICE 470, README.md 17632, banner.jpg,
chat_template.jinja 4168, config.json 726, generation_config.json 181,
merges.txt, model.safetensors 1503300328, tokenizer.json, tokenizer_config.json, vocab.json
```

So: **BF16 `model.safetensors` is public and ungated** (`"gated": false`,
`"private": false`). Finetuning is not blocked. `superwhisper/s1-mini-GGUF` additionally
publishes an `f16` GGUF, but for training you want the safetensors repo.

Caveats:

* **No `v1` tag exists**, although the card says "Releases are tagged, so you can pin
  one: `from_pretrained("superwhisper/s1-mini", revision="v1")`". The refs API returns
  `{"tags": [], "branches":[{"name":"main", ...}]}`, and
  `https://huggingface.co/superwhisper/s1-mini/raw/v1/config.json` returns **404**. Pin
  by commit sha instead: `revision="88f6b15896c73bbb13a3b596e0afe8ea0d5150b4"`.
* The weights have been updated in place. Commit titles include `Add s1-mini v075`
  (2026-08-12) and `Update to v076` (2026-08-19). Expect more updates — the maintainer
  said so in a discussion (§7).
* No training code, dataset, or eval harness is published. The `superwhisper` org has
  **zero datasets** and only these two model repos plus one Space.

**Does this allow finetuning and redistribution? Yes, with three duties.** Apache 2.0
explicitly permits derivative works. Concretely, for a "S1-mini German" you must:

1. keep the `LICENSE` text and the `NOTICE` file with your distribution (Apache 2.0 §4a, §4d);
2. state that you changed it — "state significant changes" (Apache 2.0 §4b); the card
   repeats this: "you must retain the license text and the NOTICE file, and state
   significant changes if you redistribute a modified version";
3. still identify the model as **"S1-mini" by "Superwhisper"** with that exact
   capitalization, even inside a product under a different name. The maintainer enforced
   spelling in discussion #4: "the model name must be exactly \"S1-mini\" and the company
   name must be \"Superwhisper\". Other variations such as \"S1-Mini\" should not be used."
   (https://huggingface.co/superwhisper/s1-mini/discussions/4)

So a German derivative should be named e.g. "S1-mini (German finetune by ...)", not
renamed outright. The card also warns: "If you are bundling S1-mini into a commercial
dictation app or redistributing the weights yourself, confirm the terms cover your case
rather than assuming they do." Nothing here blocks a private, local finetune for yappr.

## 4. Documented prompt format

**System prompt (exact string, required):**

```
You are a text normalizer for speech-to-text transcripts. The input begins with a control line specifying the styling, structure, and context settings; clean the transcript to match those settings and output only the cleaned text.
```

This is byte-identical to `crates/yappr-core/src/normalize.rs:23` (`SYSTEM_PROMPT`), so
yappr is already on the documented format.

**User message:** one control line, a newline, then one raw transcript:

```
[Styling: <value>] [Structure: <value>] [Context: <value>]
<raw transcript>
```

| Axis | Values | Effect (card) |
|---|---|---|
| `Styling` | `casual`, `semi-casual`, `semi-formal`, `formal` | "Sets the register: how much capitalization, apostrophe and contraction cleanup to apply." |
| `Structure` | `prose`, `lists` | list only if >= 3 items; otherwise stays prose |
| `Context` | `general`, `email` | `email` adds greeting line + sign-off block |

"The three axes are independent and every combination was trained."

Register detail (card): `casual` = all lowercase, apostrophes stripped, usually no final
period. `semi-casual` = capitalizes only `I`, sentence starts stay lowercase. `semi-formal`
= full capitalization and punctuation, contractions kept, `gonna` -> `going to`. `formal`
= contractions expanded. Fillers (`um`, `uh`) are removed in every register.

**Full raw prompt, thinking off:**

```
<|im_start|>system
You are a text normalizer for speech-to-text transcripts. The input begins with a control line specifying the styling, structure, and context settings; clean the transcript to match those settings and output only the cleaned text.<|im_end|>
<|im_start|>user
[Styling: semi-formal] [Structure: prose] [Context: general]
<raw transcript><|im_end|>
<|im_start|>assistant
<think>

</think>

```

i.e. the assistant prefix is `<|im_start|>assistant\n<think>\n\n</think>\n\n` — two
newlines inside the think block and two after it. **This exact prefix must also be used in
finetuning data**, otherwise a German finetune will drift from the shipped chat template.

**Documented failure modes:**

* Missing/altered system prompt or control line, or out-of-set values -> "the model can
  hallucinate or produce garbled output".
* Thinking left on -> "you will usually get **no usable output at all**: the model emits an
  empty `<think>` block and stops. This is the single most common way to get a blank
  result from this model." In llama.cpp: `--jinja --chat-template-kwargs
  '{"enable_thinking":false}'`; explicitly do **not** use `--reasoning-budget 0` ("it
  suppresses the think block a different way and degrades the output").
* Filler-only or noise-only input correctly returns an **empty string** — a valid result,
  not a failure.
* Long input: "keep single passes under roughly 1,000 tokens", chunk at sentence
  boundaries. Sizing rule: `1.3 x input_tokens + 32` for `max_new_tokens`.
* Decoding must be greedy; `generation_config.json` ships `"do_sample": false`.
* Not a chat model: "will not follow general instructions".

## 5. Multilingual / German support — explicitly NOT supported

The card is unambiguous and repeats it three times:

* front matter: `language: - en`
* "This is release v1, and it covers **English only**."
* overview table: "| Language | English |"
* evaluation: "Evaluated on a held-out **English** test set of 7,519 cases ... 94.8% token
  accuracy, measured greedy on the Q4_K_M GGUF build."

The strings "German", "Deutsch", and "multilingual" do not appear anywhere in either model
card. There is no roadmap statement about other languages in the cards or in the four open
discussions.

Practical consequence for yappr: today S1-mini is run on German dictation outside its
trained distribution. Number/date/currency inverse text normalization rules are
English-specific ("March 3, 2026", `$23,450`), and the German conventions (3. März 2026,
23.450 €, capitalized nouns, Sie/du register) were never trained. This is the strongest
argument for a German finetune, and also the reason yappr's guardrail matters.

## 6. Published training details — essentially none

Nothing beyond these statements:

* "Fine-tuned from Qwen/Qwen3-0.6B", "fine-tuned for a single transformation task".
* "The model expects the system prompt, then a control line, a newline, and one raw ASR
  transcript, which will usually arrive lowercase and unpunctuated. That is the shape it
  was trained on."
* "The three axes are independent and every combination was trained."
* "S1-mini was trained with thinking off and has no reasoning traces in its training data."
* Eval only: "held-out English test set of 7,519 cases covering real ASR output and
  synthetic stress sets for numbers, self-corrections, lists, email and adversarial
  inputs".

**Not published:** no dataset, no SFT vs LoRA statement, no hyperparameters, no sequence
length used at training time (only the *inference* recommendation of ~1,000 tokens), no
training code, no paper. The only cited arXiv id (2505.09388) is the Qwen3 technical
report, not an S1-mini paper. The `superwhisper` HF org publishes no datasets.

Author statement on base-model choice, discussion #2
(https://huggingface.co/superwhisper/s1-mini/discussions/2), user asked whether other tiny
base models were tried:

> [softmaximalist] We haven't explored many base models as the all the other components
> are much more important except certain cases. However, we are already using our
> knowledge and learnings from S1-mini to keep improving and also work on future models.

## 7. Other findings that matter for yappr

**The official Q4_K_M has reported quality problems** — this is the exact file yappr
pins. Discussion `s1-mini-GGUF#1`
(https://huggingface.co/superwhisper/s1-mini-GGUF/discussions/1):

> The Q4_K_M GGUF that Superwhisper provides has some quality issues, especially on longer
> transcripts. ... First, it will often get stuck in repetition loops. ... In the worst
> case, it repeated the same word "programmatically" endlessly until llama.cpp hit the max
> context limit. Second, it will sometimes change the transcript in a substantial way that
> is not just formatting. Like omitting entire parts of the transcript ... I was using the
> GGUFs at https://huggingface.co/liodon-ai/s1-mini-imatrix-GGUF. With the Q4_K_M imatrix
> GGUF, I observed noticeably higher quality at the same size, with no repetition loops,
> and with the Q6_K imatrix GGUF, I observed no noticeable difference between its output
> and the Hugging Face Space.

Maintainer reply: "We are working on making improvements to S1-mini ... A newer version of
the model should be released soon". So: an imatrix Q4_K_M or a Q6_K is a cheap quality win
for yappr independent of any German work, and any German finetune should be quantized
**with an imatrix built from German calibration text**.

**Reference inference settings** (Space `app.py`, the config the published quality numbers
are seen at): `torch_dtype=torch.bfloat16`, `attn_implementation="sdpa"`,
`enable_thinking=False`, `do_sample=False`, `max_new = min(1024, int(input_len*1.3)+32)`.

## 8. What this means for a German finetune (assessment)

Feasible. Nothing blocks it:

* Weights: BF16 safetensors, public, ungated, 596M unique params — LoRA fits in a few GB
  of VRAM, full SFT fits on one 24 GB card easily.
* Tokenizer: Qwen3 BPE, already multilingual, no vocabulary work needed.
* License: Apache 2.0 + naming clause — finetune and redistribute allowed; keep LICENSE +
  NOTICE, state changes, keep the name "S1-mini" by "Superwhisper" visible.
* Format: fully documented, so training data can be generated in the exact shipped shape
  (system prompt + control line + `<think>\n\n</think>` prefix).

The real work is data, not modelling: there is no public dataset and no recipe, so a
German set of (raw ASR transcript -> clean German text) pairs across all 4x2x2 control
combinations has to be built — most cheaply by generating German dictation-style text with
a larger LLM, degrading it into ASR-like input (lowercase, no punctuation, fillers, false
starts, spoken numbers/dates/currency), and using the clean side as the target. Watch two
risks: catastrophic forgetting of English (mix English pairs back in if English must keep
working), and preserving the empty-string-on-filler behavior.

Two open decisions worth flagging: whether to wait for the announced next upstream version
before spending on data, and whether to base the finetune on the pinned sha
`88f6b158...` so results stay reproducible.
