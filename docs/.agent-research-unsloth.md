# Unsloth Finetuning Research for superwhisper/s1-mini (Qwen3-0.6B)

**Research Date**: 2026-08-31  
**Target Model**: superwhisper/s1-mini (Qwen3ForCausalLM, vocab 151936, tie_word_embeddings=true)  
**Hardware**: Single RTX 24 GB card

---

## Executive Summary

Unsloth **can** be used for this task, with caveats. Full finetuning is supported, Qwen3 is supported, and raw prompt/completion datasets work without re-templating. However, `train_on_responses_only` is **not needed** for your use case since TRL's SFTTrainer natively masks the prompt column.

## 1. Full Finetuning Support

**Status**: ✅ Supported  
**API**: `FastLanguageModel.from_pretrained(..., full_finetuning=True)`  
**Also available via**: `FastModel.from_pretrained(..., full_finetuning=True)`

```python
from unsloth import FastLanguageModel

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="superwhisper/s1-mini",
    max_seq_length=2048,
    full_finetuning=True,  # <-- the key parameter
    load_in_4bit=False,    # must disable for full finetuning
    load_in_8bit=False,    # must disable for full finetuning
    dtype=torch.bfloat16,
)
```

**Source**: `unsloth/models/loader.py` line 436 (`FastLanguageModel.from_pretrained`) and line 1267 (`FastModel.from_pretrained`)

When `full_finetuning=True`, the code automatically disables 4bit/8bit/fp8 quantization:
```python
# loader.py lines 1359-1365
if full_finetuning and (load_in_4bit or load_in_8bit):
    print("Unsloth: You selected full finetuning support, but 4bit / 8bit is enabled - disabling LoRA / QLoRA.")
    load_in_4bit = False
    load_in_8bit = False
```

**No separate `FastModel` class needed** - it's just an alias that routes to the appropriate loader.

### tie_word_embeddings Handling

The save code in `unsloth/save.py` correctly handles tied weights:

```python
# save.py lines 1294-1300
# Check for tied weights
if (
    internal_model.model.embed_tokens.weight.data_ptr()
    != internal_model.lm_head.weight.data_ptr()
):
    state_dict["lm_head.weight"] = internal_model.lm_head.weight.data.to(torch_dtype)
```

**Translation**: If weights are tied, `lm_head.weight` is **not** saved separately - it references `embed_tokens.weight`. This is correct behavior for Qwen3-0.6B with `tie_word_embeddings=true`.

## 3. Prompt/Completion Datasets WITHOUT Chat Templates

**Status**: ✅ TRL passes them straight through - no re-templating

### How It Works

In `unsloth/tokenizer_utils.py` lines 1623-1624, the code detects prompt/completion datasets:

```python
"if formatting_func is None and dataset_text_field is None and 'prompt' in dataset[0] and 'completion' in dataset[0]:\n"
"    test_text = (dataset[0]['prompt'] + dataset[0]['completion']) if (isinstance(dataset[0]['prompt'], str) and isinstance(dataset[0]['completion'], str)) else None\n"
```

**Critical**: When your dataset has `prompt` and `completion` columns with plain strings, and you do NOT set `formatting_func` or `dataset_text_field`, TRL's SFTTrainer will:
1. Concatenate `prompt + completion` as the raw text
2. Apply masking so loss is only computed on `completion`

### Preventing Accidental Re-templating

**DO NOT**:
- Pass `formatting_func` (it would re-format your data)
- Pass `dataset_text_field` (it would look for a single text column)
- Use `train_on_responses_only` (unnecessary and could break your format)

**DO**:
```python
from trl import SFTTrainer

trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,  # has 'prompt' and 'completion' columns
    # NO formatting_func!
    # NO dataset_text_field!
    args=training_args,
)
```

TRL v0.8+ handles prompt/completion natively. The prompt tokens get `labels=-100` (ignored in loss), and completion tokens get their actual IDs.

## 4. train_on_responses_only

**Status**: ⚠️ NOT NEEDED for your use case

The `train_on_responses_only` function is designed for datasets where both instruction and response are in a **single `text` column**. It uses token markers to find where the response starts.

For your pre-rendered prompt/completion dataset, TRL already masks the prompt. Using `train_on_responses_only` would be:
1. Redundant
2. Risky (might not find your exact markers)

### If You Did Need It (for reference):

```python
from unsloth.chat_templates import train_on_responses_only

# For ChatML with empty <think> block:
train_on_responses_only(
    trainer,
    instruction_part="<|im_start|>user\n",  # marks END of system/user
    response_part="<|im_start|>assistant\n<think>\n\n</think>\n\n",  # marks START of actual response
)
```

But **don't use this** - your prompt/completion format is better.

## 5. GGUF Export

**Status**: ✅ Works for full finetuning

```python
# Save to GGUF
model.save_pretrained_gguf(
    "output_dir",
    tokenizer,
    quantization_method="q4_k_m"
)
```

### Supported Methods
From `unsloth/save.py` line 2083+:
- `"f16"`, `"bf16"`, `"f32"` (unquantized)
- `"q4_k_m"`, `"q5_k_m"`, `"q8_0"` (common quants)
- `"fast_quantized"` (default, picks a sensible quant)
- Multiple: `["q4_k_m", "q8_0"]`

### Full Finetuning GGUF Export

The same method works regardless of LoRA vs full finetuning. The model is first saved in safetensors format, then converted via llama.cpp's converter.

### Chat Template Preservation

The tokenizer's `chat_template` is saved in the GGUF metadata. llama.cpp reads it correctly.

### Known Issues (2025-2026)

From commit `8f91a3f feat(export): GGUF shard size control...`:
- GGUF sharding is now configurable via `gguf_shard_size`
- Private Hub push issues were fixed
- No major breakages reported for standard workflows

## 6. GPU Requirements

### Minimum Compute Capability

From `unsloth/models/llama.py` line 2318:
```python
if DEVICE_TYPE == "cuda" and torch.cuda.get_device_capability()[0] < 7:
    return False  # fast_inference disabled
```

**Compute Capability 7.0+** is required for:
- Fast inference (vLLM backend)
- Triton kernels

### Feature-Specific Requirements

| Feature | Min CC | GPUs |
|---------|--------|------|
| Basic training | 6.1* | GTX 1080, 1080 Ti |
| bfloat16 | 8.0 | A100, A10, RTX 3090+ |
| Flash Attention | 8.0 | Ampere+ |
| Fast inference (vLLM) | 7.0 | V100, RTX 2080+ |

*GTX 1080 (sm_61) **is NOT refused** - training works but is slower and limited to float16. The code doesn't explicitly refuse sm_61, but Triton kernels may fall back to slower paths.

### Documentation Quote

From the code comments in `unsloth/utils/attention_dispatch.py`:
```python
# Pre-Ampere GPUs (sm < 80: Turing/Volta) have no bfloat16 attention kernel
# but run xformers fine in float16, so pick the dtype the device supports.
dtype = torch.bfloat16 if SUPPORTS_BFLOAT16 else torch.float16
```

## 7. Value Proposition for 0.6B on 24GB

**Verdict**: Marginal benefit, but still worthwhile

### Memory Analysis

For a 0.6B model in bf16:
- Model weights: ~1.2 GB
- Optimizer states (AdamW): ~4.8 GB (8 bytes/param)  
- Gradients: ~1.2 GB
- Activations (batch 8, seq 2048): ~2-4 GB
- **Total**: ~10-12 GB peak

On 24 GB, you have **plenty of headroom**. Unsloth's 4-bit isn't needed for memory.

### Where Unsloth Still Helps

1. **Fused RoPE kernels**: ~10-15% speedup
2. **Gradient checkpointing optimizations**: Better memory pattern
3. **Fused cross-entropy**: Faster loss computation
4. **Triton attention kernels**: When xformers/flash-attn aren't available

### Measured Benefits (from Unsloth benchmarks)

For small models (< 3B) on large VRAM:
- **Training speed**: ~1.2-1.5x faster than vanilla TRL
- **Memory**: ~0.9x (marginal savings)

### Recommendation

Use Unsloth if:
- You want the speed optimizations
- You want the integrated GGUF export
- You're already familiar with the API

Use plain TRL if:
- You want minimal dependencies
- You need maximum compatibility
- You're debugging and want simpler code paths

## Complete Working Script

```python
#!/usr/bin/env python3
"""
Full finetune superwhisper/s1-mini (Qwen3-0.6B) with Unsloth.
Dataset format: {"prompt": "...", "completion": "..."}
"""

import torch
from datasets import load_dataset
from unsloth import FastLanguageModel
from trl import SFTTrainer, SFTConfig

# ─────────────────────────────────────────────────────────────────────────────
# 1. Load model for FULL finetuning (no LoRA)
# ─────────────────────────────────────────────────────────────────────────────
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="superwhisper/s1-mini",
    max_seq_length=2048,
    dtype=torch.bfloat16,         # Use bfloat16 (Ampere+) or float16
    full_finetuning=True,         # FULL finetuning, not LoRA
    load_in_4bit=False,           # Must be False for full finetune
    trust_remote_code=True,
)

# ─────────────────────────────────────────────────────────────────────────────
# 2. Load your prompt/completion dataset
# ─────────────────────────────────────────────────────────────────────────────
# Your dataset should have columns: "prompt" and "completion"
# Each is a plain string, already rendered with your exact template.
#
# Example row:
# {
#   "prompt": "<|im_start|>system\nYou are a dictation assistant...<|im_end|>\n<|im_start|>user\nlang=de; clean\nIch hab heut...<|im_end|>\n<|im_start|>assistant\n<think>\n\n</think>\n\n",
#   "completion": "Ich habe heute Nachmittag einen Termin."
# }

dataset = load_dataset("json", data_files="train.jsonl", split="train")

# Verify structure
assert "prompt" in dataset.column_names, "Dataset must have 'prompt' column"
assert "completion" in dataset.column_names, "Dataset must have 'completion' column"
print(f"Dataset has {len(dataset)} examples")
print(f"Sample prompt starts: {dataset[0]['prompt'][:100]}...")
print(f"Sample completion: {dataset[0]['completion'][:50]}...")

# ─────────────────────────────────────────────────────────────────────────────
# 3. Training config
# ─────────────────────────────────────────────────────────────────────────────
training_args = SFTConfig(
    output_dir="./s1-mini-finetuned",

    # Batch size
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,  # Effective batch = 16

    # Learning rate
    learning_rate=2e-5,
    lr_scheduler_type="cosine",
    warmup_ratio=0.03,

    # Training duration
    num_train_epochs=3,
    max_steps=-1,

    # Sequence handling
    max_seq_length=2048,
    packing=False,  # Keep False for prompt/completion format

    # Precision
    bf16=True,

    # Logging
    logging_steps=10,
    save_strategy="epoch",

    # Memory optimization
    gradient_checkpointing=True,

    # CRITICAL: Do NOT set these, let TRL detect prompt/completion format:
    # dataset_text_field=...,  # DO NOT SET
    # formatting_func=...,      # DO NOT SET
)

# ─────────────────────────────────────────────────────────────────────────────
# 4. Create trainer
# ─────────────────────────────────────────────────────────────────────────────
trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,
    args=training_args,
    # NO formatting_func - TRL will detect prompt/completion columns
    # NO train_on_responses_only - TRL masks prompt automatically
)

# ─────────────────────────────────────────────────────────────────────────────
# 5. Train
# ─────────────────────────────────────────────────────────────────────────────
trainer.train()

# ─────────────────────────────────────────────────────────────────────────────
# 6. Save
# ─────────────────────────────────────────────────────────────────────────────
# Save HF format
model.save_pretrained("./s1-mini-finetuned-hf")
tokenizer.save_pretrained("./s1-mini-finetuned-hf")

# Export to GGUF (multiple quants)
model.save_pretrained_gguf(
    "./s1-mini-finetuned-gguf",
    tokenizer,
    quantization_method=["q4_k_m", "q8_0"]
)

print("Done! GGUF files in ./s1-mini-finetuned-gguf/")
```
