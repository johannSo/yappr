# Parakeet TDT 0.6b v3 — empirical evidence on GERMAN output

Research date: 2026-09 (agent run). Model: `nvidia/parakeet-tdt-0.6b-v3`, ONNX/int8 port
`csukuangfj/sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8`.

**Method note / limitation.** The Serper web-search key is not configured in this environment, so
Google search was unavailable. DuckDuckGo blocked automated queries (HTTP 403) and reddit.com
returned 403 / connection refused, so **no Reddit thread could be read**. Evidence below comes from
sources reachable by direct API: HuggingFace model/space discussion APIs, the GitHub issue-search
API, raw model cards, arXiv, and one German blog. In addition I ran the model **locally** on real
German audio (see §7) — that part is first-hand measurement, not a report.

Everything marked **[SOURCED]** has a URL and a quote. Everything marked **[INFERENCE]** is my
reasoning, not a report. Gaps are stated as gaps.

---

## 0. Summary answers

| Question | Answer | Confidence |
|---|---|---|
| 1. German noun capitalization | Present and mostly correct in real transcripts, not merely sentence-initial; errors do occur (`dinge`, missing final stop) | High (own run §7 + user transcript §3) |
| 2. Umlauts / ß | Produced correctly by the model; `ß` is in the vocabulary and appears in output. Reported "broken umlaut" cases were **downstream encoding bugs**, not ASR | High |
| 3. Numbers | Digits for years/large numbers, spelled-out words for small numbers; inconsistent (documented for French by an NVIDIA-repo user, same ITN mechanism) | Medium-High |
| 4. Fillers | Largely absent from output; "äh"/"ähm" is representable (token exists) but training targets are Whisper pseudo-labels + LLM-cleaned | Medium |
| 5. Error patterns | Wrong-language/cross-alphabet leakage into German (Greek reported), whole dropped sentences, weak dialect handling (~55 % WER bucket), sentence-boundary/punctuation drift | Medium-High |
| 6. vs Whisper large-v3 (German) | Roughly equal on clean read speech; v3 clearly worse on Tuda-De (7.05 vs 7.86 — actually better there) and much worse in one independent podcast test (12.56 % vs 2.24 % WER) | Mixed evidence |

## 1. What NVIDIA itself claims, and how German text was produced

**[SOURCED]** Model card, https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3 (raw README):

> "`parakeet-tdt-0.6b-v3`'s key features ... include: * Automatic **punctuation** and **capitalization** * Accurate **word-level** and **segment-level** timestamps ..."

So punctuation and capitalization are an advertised output property, for all 25 languages including
German (`de`).

**[SOURCED]** Training-data provenance, Canary-1B-v2 / Parakeet-v3 report, arXiv 2509.14128
(https://arxiv.org/html/2509.14128v2):

> "For our second model, Parakeet-TDT-0.6B-v3, we trained exclusively on the ASR subset of the
> Canary-1B-v2 training set (~660,000 hours across the same 25 languages)."

> "To enhance model robustness against hallucinations, particularly those potentially inherited from
> **Whisper-based pseudo-labeling**, we incorporated 36,000 hours of non-speech audio ..."

**[SOURCED]** Granary dataset paper, arXiv 2505.13404 (https://arxiv.org/html/2505.13404v2), §3.1.5
"LLM-Powered P&C Restoration":

> "The Granary corpus relies on pseudo-labeled data from Whisper, necessitating steps to enhance
> quality ... we applied punctuation and capitalization restoration using the large language model
> **Qwen 2.5-7B-Instruct**. We crafted a language-specific prompt directing the model to assess and
> correct punctuation and capitalization ... A heuristic was used: if Qwen's output deviated from
> Whisper's transcriptions by more than a 5% character error rate, the original pseudo-labels were
> retained."

**[INFERENCE]** German capitalization in v3 is therefore "whatever Whisper wrote, corrected by a
German-prompted Qwen 2.5-7B, unless the correction was large". That predicts: good but not perfect
German noun capitalization, Whisper-style number formatting (digits for years/prices), and few
fillers — because Whisper's German output rarely contains "äh"/"ähm". §7 confirms all three.

**[SOURCED]** Vocabulary check (hard evidence, `tokens.txt` of the sherpa int8 build,
https://huggingface.co/csukuangfj/sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8/raw/main/tokens.txt):
8193 tokens. It contains the digit tokens `0`–`9`; 194 tokens containing `ä ö ü ß`, including
`▁für`, `▁über`, `▁können`, `▁weiß`, `ß`, `ßen`, `iß`; 448 tokens that start a capitalized word
(`▁De`, `▁St`, ...); and punctuation `, . ? ! : -`. A filler token `äh` exists.
So digits, umlauts, `ß` and capitals are all representable; nothing is blocked by the vocabulary.

## 3. The one real German transcript posted publicly by a user

**[SOURCED]** EnviousWispr (macOS dictation app whose default engine is Parakeet TDT v3 via
FluidAudio) issue #2450, quoting user "Markus", 2026-08-26:
https://github.com/saurabhav88/EnviousWispr/issues/2450

> "Für das CrefoZert benötigen wir die Bilanz 2025. 2025 wollte mir schon zur Verfügung stellen.
> Allerdings ist noch nicht so weit. **Punkt.** Es hängt immer noch beim Steuerberater, weil für die
> Förderung, die mit einbauen wollte, noch drei Fragen zu beantworten sind, diese muss auch noch
> liefern. **Neuer Absatz.** Hat sich das auf ein Zettel geführt. Geschrieben für das Wochenende, weiß
> allerdings nicht, ob das noch schafft, weil ab Dienstag für wahrscheinlich drei Wochen. In Berlin ist
> zur IFA und zur Basketballweltmeisterschaft. Ansonsten machen wir das dann. Ende September.
> **Punkt. Neuabsatz.** Ich bekomme aber bis Ende der nächsten Woche noch eine Info. Wie stand der
> dinge ist"

What this single sample shows (my reading of it):

- **Noun capitalization is real German capitalization**, not sentence-initial only: `Bilanz`,
  `Verfügung`, `Steuerberater`, `Förderung`, `Fragen`, `Zettel`, `Wochenende`, `Dienstag`, `Wochen`,
  `Info`. Brand casing survived: `CrefoZert`.
- **But it is not reliable**: the last clause reads "Wie **stand** der **dinge** ist" — noun `Dinge`
  lowercased, verb-form `Stand` mis-cased, and no final period.
- **Compound nouns are NOT split**: `Basketballweltmeisterschaft` came out as one word.
- **Umlauts and ß are correct**: `benötigen`, `hängt`, `Förderung`, `weiß`.
- **Numbers**: year as digits (`2025`, twice); small counts as words (`drei Fragen`, `drei Wochen`).
- **Dictated punctuation words are transcribed literally** ("Punkt", "Neuer Absatz") — that is the app's
  bug, but it also shows the ASR does not do German spoken-punctuation commands itself.
- Real recognition errors: dropped/garbled clauses ("wollte mir schon zur Verfügung stellen",
  "Hat sich das auf ein Zettel geführt").
- Sentence boundaries are placed oddly: "Ansonsten machen wir das dann. Ende September." — a
  **sentence-boundary error** splitting one sentence in two.

**Caveat [SOURCED context]:** that app runs its own post-processing, so filler removal and polish may
have touched the text before the user pasted it. It is still the only public German v3 transcript I found.

## 4. Umlauts / ß

- **[SOURCED]** The only public "German umlauts are broken" report I found is
  https://github.com/stephan271c/WhisperNow/issues/1 — a Windows app using
  `sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8` (exactly our model file):
  > "Umlauts (ä, ö, ü, ß) are present correctly in the Enhanced Text. However, the final output text is
  > not displayed correctly in a German Windows Notepad ... **German transcription itself works as
  > expected.**"
  > "Leider werden Umlaute wie das ├£ in ÔÇ×├£berraschungÔÇ£ ... nicht richtig konvertiert."
  Root cause and fix were UTF-8 vs Windows-1252 encoding in the app, confirmed fixed in v0.1.1rc1.
  **So: an encoding bug downstream, not an ASR defect.**
- **[SOURCED]** Vocabulary contains `ß` (`▁weiß`, `ßen`, `iß`, `ß`) — see §1.
- **No source found** reporting systematic `ss`-for-`ß` substitution by v3.
  Note that Swiss-German orthography legitimately writes `ss`, and one German reference corpus line I
  used in §7 contains "nicht bloss der scipionische Kreis" — so a *reference* may spell `ss` where the
  model writes `ß` and vice versa. **[INFERENCE]** this is a normalization question, not an error class.

## 5. Numbers, fillers, and post-processing evidence from a German-heavy dictation product

The most detailed German-Parakeet-v3 material I found anywhere is the issue tracker of
`saurabhav88/EnviousWispr` — a Mac dictation app whose default engine is Parakeet TDT 0.6b v3 and
whose largest market is Germany. Treat it as one vendor's measurements, but the numbers are stated
with method.

- **[SOURCED]** #1411 — "Deterministic number/date/money formatting (ITN) silently no-ops for
  non-English dictation (Parakeet path) — confirmed on German users":
  https://github.com/saurabhav88/EnviousWispr/issues/1411
  > "Germany (434 dictations) ... ITN actually changed the text **3.7%** | USA, same window (675
  > dictations) **17.2%**"
  **[INFERENCE]** Their English ITN layer finds almost nothing to do on German text. Combined with §7,
  the reason is that the *model* already emits digits where a German writer would, and their
  German-word→digit rules do not exist.
- **[SOURCED]** #2259 — filler words. Their filler stripper deletes `um|umm|uh|uhh|hmm|mm|mhm|mmm|ah|er`
  and a German user complained it eats real German words:
  > "In German, the word 'Er' isn't a filler word—it corresponds to the English 'he.' However, the AI
  > deletes the word 'er' from the text"
  https://github.com/saurabhav88/EnviousWispr/issues/2259
  **[INFERENCE]** Notable for us: their German complaint is about *false-positive filler deletion*, not
  about "äh/ähm" surviving. Nobody in that tracker reports German fillers appearing in Parakeet output.
- **[SOURCED]** #1678 — wrong-language leakage in German, a real user report (R. Schepers, 2026-07-12):
  > "I selected Fast Mode because I only speak German in the app. Unfortunately, it often happens that
  > **other languages, such as Greek, are recognized**."
  and the FluidAudio doc they quote:
  > "Parakeet TDT v3 is a multilingual model with a single shared SentencePiece vocabulary spanning
  > Latin and Cyrillic alphabets. **On short utterances with ambiguous audio, the joint network can emit
  > wrong-language tokens**"
  https://github.com/saurabhav88/EnviousWispr/issues/1678
- **[SOURCED]** #1982 — a 512-clip German benchmark of `nvidia/parakeet-tdt-0.6b-v3` (native NeMo)
  against the German fine-tune `primeline/parakeet-primeline` and WhisperKit large-v3-turbo:
  https://github.com/saurabhav88/EnviousWispr/issues/1982

  | configuration | raw WER | format-aware WER |
  |---|---:|---:|
  | Parakeet v3 multilingual, auto | 4.85 % | 4.55 % |
  | primeline German Parakeet | 5.67 % | 4.72 % |
  | WhisperKit large-v3-turbo, auto | 5.53 % | 5.30 % |
  | WhisperKit large-v3-turbo, `--language de` | 5.75 % | 5.53 % |

  Per-bucket, for v3 (n in brackets): **dialect vocabulary 55.81 % WER (10)** — i.e. dialect is
  effectively broken; regional Austrian/Swiss accent 1.15 % (10); real unscripted human speech 9.61 %
  (120); proper nouns 3.23 % (15); long sentences 3.68 % (28).

  And — directly relevant to formatting — their "format-aware rescoring" comment lists **actual German
  hypotheses of the v3 model** against references:
  ```
  ref  Die Rechnung beläuft sich auf 1.250 Euro netto.
  hyp  Die Rechnung beläuft sich auf 1250 Euro netto.     -> scored 22% WER
  ref  Herr Doktor Weber und Frau Professor Schneider ...
  hyp  Herr Dr. Weber und Frau Prof. Schneider ...          -> scored 15% WER
  ref  Erstens: die Anreise. Zweitens: die Unterkunft.
  hyp  1. Die Anreise. 2. Die Unterkunft.                   -> scored 33% WER
  ```
  > "Several of the international model's 'errors' are style, not mishearing ... thousands separator,
  > decimal comma, clock punctuation, abbreviation spelling (Dr./Doktor), digits vs number words,
  > ordinal words."

  This is the clearest German number evidence available: **v3 writes digits (`1250`, `1.`, `2.`) and
  abbreviations (`Dr.`, `Prof.`), and it does NOT insert the German thousands separator (`1250`, not
  `1.250`)**. Nouns in those hypotheses are correctly capitalized (`Rechnung`, `Euro`, `Anreise`,
  `Unterkunft`).

## 7. First-hand measurement: I ran the model this project ships

Not a report — I decoded real German audio with the exact artefact in
`~/.local/share/yappr/models/parakeet-tdt-0.6b-v3-int8` through the repo's own example
(`cargo build --release -p yappr-core --example transcribe_file`). No microphone was used.

**Audio:** 30 clips from `flozi00/asr-german-mixed` (16 kHz, sources: Common Voice 19.0,
Multilingual LibriSpeech German, Tuda-De), fetched through the HF datasets-server, plus the
`test_wavs/de.wav` shipped with the sherpa model.

**Aggregate over the 30 clips (660 reference words):** approximate WER 11.4 % (my crude
token alignment, no normalization — so it double-counts the spelling/formatting differences
described below). Capitalized-word rate: **hypothesis 28.5 %, reference 27.6 %** — the model
capitalizes at native German density.

### 7.1 Noun capitalization — YES, real German capitalization
Every common noun in my 30 outputs is capitalized: `Wettbewerb, Mannschaften, Brotdose,
Nachrichtenmagazine, Korrektheit, Reaktionen, Desaster, Hinsicht, Nachtfee, Mondberg, Kindern,
Bäume, Häuser, Schwärmer, Lemuren, Bestäubung, Gedächtnis, Prinz, Fähre, Kriegserklärung,
Beobachtungen, Verspottung, Handelsroute, Dringlichkeit, Hütte, Stützpunkt, Langläufer,
Skitourengeher, Geröll, Hartstein, Wurfgeschosse, Berichterstatter, Orthographie, Aussprache,
Aufstand, Landschaften, Einmarsch, Truppen, Rosinante, Laus, Gymnastik, Voraussetzungen, Mädchen,
Hut, Locken, Fahne`.

Zero cases in my sample of a noun being left lowercase. The only case-level differences against the
reference were:
```
22.wav  ref "die Philosophische Fakultät"   hyp "die philosophische Fakultät"   (proper-name casing lost)
19.wav  ref "er tut unrecht"                hyp "er tut Unrecht"                (arguably the better spelling)
27.wav  ref "sahen sie nicht aus"           hyp "sahen Sie nicht aus"           (wrong polite-form capital)
28.wav  ref "Als eine Fortbildung ..."      hyp "als eine Fortbildung ..."      (SENTENCE-INITIAL LOWERCASE)
```
So capitalization is good but not perfect, and **sentence-initial capitalization can fail** (28.wav
starts lowercase) — the model treats a clip as a mid-sentence continuation when the audio starts
mid-sentence.

### 7.2 Umlauts and ß — correct, and the model PREFERS ß
51 umlaut characters in the hypotheses vs 52 in the references. No mojibake, no dropped umlauts.

The `ß` behaviour is the opposite of the feared one: this corpus's references use Swiss `ss`
spellings, and the model wrote `ß`:
```
05.wav  ref "nicht bloss der scipionische Kreis"   hyp "nicht bloß der skipionische Kreis"
21.wav  ref "auf einen scharfen Hartstein zu stossen"  hyp "... zu stoßen"
```
**No evidence anywhere of `ss` being emitted where `ß` is correct.**

### 7.3 Numbers — evidence is thin and points to digits
My 30 clips contained no spoken numbers in the references, so I could not test this directly. The
one digit that appeared was a **hallucination**:
```
19.wav  ref "Es badet einer zu frühe, sage nicht, ..."
        hyp "45 Es badet einer zu früh. Sage nicht, ..."
```
(a leading `45` with no counterpart in the audio reference — probably a spoken section number in the
LibriSpeech recording, but it shows the model does emit bare digits into German text).

Combined with §5's German hypotheses (`1250 Euro netto`, `1. Die Anreise. 2. Die Unterkunft.`,
`Herr Dr. Weber`) and §3's `Bilanz 2025`, the picture is: **digits for years, amounts and ordinals;
number words for small counts (`drei Fragen`); no German thousands separator; abbreviations
abbreviated (`Dr.`, `Prof.`)**. It is a learned style, so it varies utterance to utterance — the
French report in §2 is the direct evidence that it is inconsistent.

### 7.4 Fillers — none appeared
`äh`, `ähm`, `ne`, `halt` appear **0 times** across my 30 outputs; `also` once (as a real adverb).
My audio is read speech, so this is weak evidence — read speech contains no fillers.
**[INFERENCE]** but the training pipeline (§1: Whisper pseudo-labels cleaned by Qwen 2.5) makes a
fluent, filler-free target style very likely, and no source anywhere in this research reports German
"äh"/"ähm" showing up in Parakeet v3 output. **Gap: nobody has published a spontaneous-German
Parakeet v3 transcript with disfluencies. This is the least-supported answer in this document.**

### 7.5 German error patterns I actually observed
- **Compound splitting — CONFIRMED, several times.**
  ```
  07.wav  ref "den bösen Holzdieb"          hyp "den bösen Holz Dieb"
  21.wav  ref "im Wasser rundgeschliffen"   hyp "im Wasser rund geschliffen"
  01.wav  ref "Wiederankurbelung"           hyp "wieder Ankup belegung"
  ```
- **Anglicism spelling — CONFIRMED.**
  ```
  00.wav  ref "Es geht um das Fairplay im Wettbewerb"   hyp "Es geht um das Fair Play im Wettbewerb"
  03.wav  ref "Lord Darnley, Marias Ehemann, dass Rizzio Marias Geliebter war"
          hyp "Lord Darnley Maria's Mann, dass Rizio Maria's Geliebter war"     <- English 's genitive
  ```
- **English-word leakage into a German sentence — CONFIRMED.**
  ```
  01.wav  hyp "... seiner Wirtschaft mehr than ihr angemessener ..."   ("than" in a German sentence)
  ```
  This matches the wrong-language leakage reported in §2/§5 (Greek in German; Swedish in Danish).
- **Sentence-boundary and terminal-punctuation errors — CONFIRMED.**
  ```
  05.wav  hyp ends "... auf Korrektheit drang,"      (comma instead of period, no final stop)
  26.wav  hyp ends "... im Zaum gehalten,"           (same)
  29.wav  ref "... wunderbar umgeben, sie schien noch atemlos."
          hyp "... wunderbar umgeben. Sie schien noch atemlos."   (comma -> period split)
  27.wav  ref "... sahen sie nicht aus, einer von ihnen sass ..."
          hyp "... sahen Sie nicht aus. Einer von ihnen saß ..."
  ```
  **Relevant to yappr's `finish::finish` choke point: the model does NOT reliably terminate an
  utterance with a period, and does not reliably capitalize the first word.**
- **Proper nouns degrade** (`Sanguntums` for `Saguntums`, `Kartarko` for `Karthago`, `Gilio` for
  `Giglio`, `Platus` for `Platos`, `skipionische` for `scipionische`) — matches the proper-noun bucket
  finding in §5.
- **Homophone confusion (das/dass, wider/wieder, seit/seid):** `dass` was written correctly in the
  clips that contained it (13.wav, 05.wav). **No instance of das/dass confusion observed, and no
  source reports one.** Not established either way.
- **Dialect:** not tested here. §5's benchmark measured **55.81 % WER on its dialect-vocabulary
  bucket** for v3 — i.e. dialect is effectively unusable.
- **Word dropping:** `14.wav` ref "nach Cooks Beach" → hyp "nach Cook's." (the last word vanished),
  consistent with the "model drops sentences" reports in §2.

### 7.6 The shipped sample
`test_wavs/de.wav` from the sherpa model repo decodes to:
> `Alles hat ein Ende, nur die Wurst hat zwei.`
Perfect: capitalized nouns (`Ende`, `Wurst`), correct comma, correct final period.

## 8. What is NOT established (evidence gaps)

- **No Reddit evidence at all** — reddit.com blocked this environment (403 / connection refused).
  r/LocalLLaMA threads on German Parakeet were not readable.
- **No HuggingFace discussion mentions German** (47 discussions checked, zero hits).
- **No German spontaneous-speech transcript with fillers** exists in any source I found, so the
  filler answer rests on training-pipeline inference plus read-speech absence.
- **No source reports `ss`-for-`ß`** — the only public umlaut complaint was an app encoding bug.
- **No dialect transcript sample** — only one aggregate 55.81 % WER bucket figure, from a single
  vendor's benchmark, on synthesized Austrian/Swiss voices.
- **The two German WER comparisons against Whisper large-v3 disagree** (§6): a vendor card says
  parity, an independent podcast test says 12.56 % vs 2.24 %. Neither has an independently verified
  German gold reference (the second author says so explicitly).
- **The EnviousWispr issue tracker (§5) is one vendor's internal, agent-written evaluation.** Its
  numbers are method-stated and self-corrected in public, which is why I used it, but it is not
  peer-reviewed and its Parakeet runtime is FluidAudio Core ML, not sherpa-onnx int8.

## 9. Practical implications for yappr's German pipeline (inference)

1. **Do not add a "capitalize German nouns" post-step.** The model already does it at native
   density (§7.1). A rule-based pass would mostly do damage.
2. **Do keep the sentence-initial capital + terminal-period choke point** (`finish::finish`) — the
   model genuinely fails both (§7.5), so this invariant is earning its keep on German.
3. **Expect digits, not number words**, and expect `1250` rather than `1.250` (§5). If German
   thousands separators or `14:30` clock formatting matter, that is post-processing work, not
   something to hope the model does.
4. **Compound splitting and anglicism spacing are the German-specific error classes to target**
   (`Holz Dieb`, `Fair Play`, `Maria's`) — a vocabulary/replacement list is the right tool, and this
   is exactly what `[[vocabulary.replacements]]` is for.
5. **Do not build filler-removal rules around `er`/`um`** — that is a documented real-world defect
   in a competitor product (§5, #2259). German fillers to consider are `äh`, `ähm`, `halt`, `ne`,
   `also`, and they mostly never reach the text anyway.
6. **Cross-language leakage is real on short utterances** (Greek in German; `than` in my own §7.5
   run). sherpa-onnx exposes no language lock for this model (the NVIDIA maintainer confirms there is
   no language conditioning at all, §2 #8), so a script/`[a-zA-ZäöüÄÖÜß]`-based sanity check in the
   guardrail is the only available defence.
